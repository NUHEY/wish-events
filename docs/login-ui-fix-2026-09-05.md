# 関係者ログイン・表示調整（2026-09-05）

## 原因と修正

ログインフォームがmethod未指定のためGETフォームと解釈され、documentのcapture段階の遷移ガードがReactのonSubmitより先に送信を中止していた。本番でも誤パスワードで送信して無反応になることを再現した。

- フォームをPOSTに指定。遷移ガードのcaptureでは遷移中の操作だけを止め、GETの画面移動判定はReactが送信を処理した後に行う。他のクライアントフォームも同じ不具合から保護する。
- React18の非同期useTransition依存をやめ、処理中表示・同期的な連打防止・25秒の通信期限・失敗後の再試行を追加。
- サーバーが設定した認証Cookieでホームへ移動。ブラウザでsetSessionとgetUserを繰り返さず、APIのJSONへ認証トークンを返さない。
- 関係者は種別とパスワードだけを入力する。内部用メール設定は任意とし、空欄やメール形式でない値は専用の既定IDに置き換える。通常の寮生の認証・ドメイン制限は維持。
- 正式名称と画像はDBの関係者種別を優先する。メニューの名前とバッジを別行にし、関係者には未設定の部屋番号を表示しない。
- 入力・選択欄の角丸を10pxへ統一。短いバッジ・カテゴリ・下部タブの折返しを防止。ツールカードの固定高さを解除。大学の英語名称は意味のある単位で折り返す。

既存47件に、フォーム送信3件、成功時の応答内容1件、内部ID・正式名称1件を追加（計52件）。51件の一括実行と、追加後の認証関連8件が成功。ビルド成功、対象lint成功。ブラウザの実コンポーネント検証画面で処理中・失敗・再試行・成功後の移動・通信期限を確認。360pxのメニュー/英語タブと、360/390/430pxの英語ログイン画面を確認した。
