# 関係者権限とスマホ表示の改善（2026-09-05）

## 利用方法

RAのアカウントメニュー → 管理ボード → 関係者の権限。
「生活窓口」「大学学生生活課」を選び、担当機能をチェックして「権限を保存」を押す。
「すべて許可」「すべて解除」に対応。切り替えても未保存の選択を保持する。

許可は閲覧だけでなく、各項目に説明した作成・編集・削除等を含む。関係者自身による再委任、RA任命、全寮生一括退寮は許可しない。
初期状態は両方とも未許可。初回ログイン前でも、種別ごとに設定できる。更新の競合は検出して再読み込みを案内する。

対象12機能：イベント、お知らせ、通知、日程・予約、質問箱、リンクページ、バッジ、寮生情報、ホーム編集、イベント選択肢、機能公開、サイト表示設定。
イベント・通知・日程・寮生管理では寮生レコードも扱うことを設定画面に明記。
ホームの便利ツール公開・密度をまとめて変更する操作には、ホームに加えて機能公開・サイト設定も必要。日程の初期設定はサイト設定へ集約。

## 実装

- 権限テーブルは2種類の関係者用に固定し、RAだけが更新できる。関係者のroleをRAに変更しない。
- メニュー、ページ、Server Action、API、DBのRLS・管理RPC・画像保存で許可範囲を照合。
- 権限取消後は次のリクエストから拒否。以前作成したイベント・日程の所有者権限による抜け道も拒否。既に表示された情報を画面から消去する機能ではない。
- 通常の寮生の参加・コメント・友達間チャット等は既存の範囲を維持。
- お知らせのみ許可した場合も専用フォルダーへ画像追加可能。他のイベント画像への上書き・削除は許可しない。

## UI基準と変更

W3CのReflow（320 CSS px）を土台に、主要な操作領域は独自基準44px以上に設定。WCAG 2.5.8のAA最低値24pxと44pxの独自基準は区別する。完全なWCAG適合監査ではない。

- [W3C Reflow](https://www.w3.org/WAI/WCAG22/Understanding/reflow.html)
- [W3C Target Size Minimum](https://www.w3.org/WAI/WCAG22/Understanding/target-size-minimum.html)
- [Supabase Row Level Security](https://supabase.com/docs/guides/database/postgres/row-level-security)

管理メニューを目的別に整理し、許可された項目だけを表示。スマホメニューは標準dialogを使い、フォーカス移動・Escape・復帰に対応。
管理ボードに作業への入口を集約し、イベント一覧は20件ずつ表示、総数は全件の集計に変更。読み込み失敗を0件と誤表示しない。
イベント一覧は380px未満を1列にし、日付と時刻を省略せず表示。長い名前・説明・バッジを適切に折り返す。
機能公開設定は目的別グループ・コンパクトな選択肢に変更。サイト設定は詳細調整を折り畳み、即時保存とボタン保存を明記。言語・テーマ・通知を含む共通操作のタッチ領域も改善。

## 検証

- JavaScriptテスト59件成功（既存52件＋権限判定・設定保存7件）。型検証成功。
- 一時PostgreSQLで従来のアカウント・退寮制御と新しい権限の回帰検証成功。自分への付与、異なる関係者の範囲、RLS/RPC、取り消し、画像保存、移行の再実行を確認。
- 本番Supabaseでロールバックによる互換性検証後、承認されたマイグレーションとお知らせ画像の補足を適用。両アカウントの許可件数0を確認。
- 実コンポーネントを使うローカル表示検証で320/360/390/430pxを確認。イベント、ツール、機能公開、サイト設定、イベント表示設定、権限画面でページ横はみ出しなし。ツールの横スクロール部分はその枠内に限定。
- 権限画面の選択保持・保存中・保存完了、RA/関係者メニューの出し分け、Escape後のフォーカス復帰を確認。保存のUI検証は検証用応答へ差し替え、実際の保存処理はユニットとDB試験で別途検証。
